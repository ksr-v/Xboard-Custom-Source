# 限速与路由更新

本说明对应后端 `v2026.10.25.1` 与独立 xboard-node `v1.13-orphan.5`；已有部署按[本次更新教程](../installation/upgrade-2026.10.25.zh-CN.md)配套更新，保留原配置和 CA。只更新 NodeEndpoint 插件不会替换节点内核。

管理员保存用户限速后，面板在数据库事务提交后直接发送 `sync.user.delta`，不再等待邮件通知队列。设备数量限制使用相同路径；普通流量统计等用户变化继续使用原来的异步队列。限速必须为非负整数，单位为 Mbps；`0` 或空值表示取消该用户限速。

修改套餐并勾选“强制更新”时，批量修改也会在事务提交后同步发送完整用户列表，不等待队列。权限组同时变化时，旧权限组与新权限组都会同步，避免旧节点保留已经移走的用户。未勾选“强制更新”仍只修改套餐，不改变现有用户或推送其限速；批量同步的请求耗时随关联节点与用户数量增加。

修改路由、删除路由，以及调整节点的路由选择顺序，会在事务提交后立即发送 `sync.config`。节点是否出现在订阅中不影响更新：`enabled=true, show=false` 的隐藏运行节点也会收到关联路由的变化。回滚的事务不会发送上述配置。路由列表按节点 `route_ids` 的选择顺序下发，前面的规则具有更高的首次匹配优先级；已删除的 ID 会被忽略，重复 ID 只下发一次。

以上是面板发送通知的时机。在线节点通过 WebSocket 接收通知，最终应用时间还取决于网络和节点内核；离线节点在重新连接时完整同步，使用 HTTP 轮询的节点按其配置周期获取变化。Redis 发布失败沿用现有日志记录，保存成功不表示节点已经确认应用。面板没有新增发布确认协议或数据库字段。

面板的 `custom_routes` 是目标内核的原生规则；`custom_outbounds` 中的 `settings` 也必须使用对应内核接受的格式。不要把 Xray 的原生配置直接当作 sing-box 配置使用。面板目前不保存或下发 Node 本地的 `custom_route_rules` 结构化规则。该本地结构化格式在同一条规则中配置多个匹配字段时，沿用原有 **OR（任一字段命中）** 语义；例如同时填写端口和 `TCP` 不会将范围缩小为“此端口且 TCP”。需要组合条件时，应使用相应内核的原生规则及其文档规定的语义。

## 后端回归验证

运行：

```bash
php tests/RateRoute/synchronization.php
```

也可以通过 `XBOARD_TEST_VENDOR` 指向已安装的本地 `vendor/autoload.php`。测试使用独立的内存 SQLite、合成用户和捕获发布器，不连接生产数据库或真实 Redis，也不启动队列工作进程。测试覆盖路由顺序、隐藏运行节点、提交与回滚、限速启停及输入校验，以及套餐强制更新、跨权限组迁移、嵌套事务回滚和普通套餐保存；真实节点流量、已有连接和内核路由应用需要在节点联测中单独验证。
