# Hysteria2 端口跳跃与节点自动 UDP 转发

跳跃 NAT 需要包含该功能的面板后端和 xboard-node。Node v8 已为实际 Hysteria2 UDP 监听口增加 owned INPUT 管理，当前 v9 保留该能力，单端口 HY2 也适用，详见[启用、关闭与防火墙边界](node-management-hy2.zh-CN.md#实际-udp-监听口自动-input)。旧 Node 忽略自动转发字段，已有节点需单独升级。

## 面板配置

在 Hysteria 节点中选择协议版本 2，分别设置：

- **连接端口**：客户端使用的单端口或连续范围，例如 `20000-21000`。
- **服务监听端口**：Node 内核实际监听的单个 UDP 端口，例如 `443`。
- **跳跃间隔**：客户端使用的正整数秒数；留空采用客户端默认值。旧表单中的 `0` 在保存时转换为留空。客户端可能另有最小间隔限制，应使用该客户端支持的值。

端口必须介于 1 和 65535，范围包含两个端点且起点不得大于终点。不接受逗号列表、混合范围、空白或反向范围；服务监听端口不能填写范围。保存失败会显示字段校验错误。其他协议的保存规则保持原状。

新版后端在 Node 配置中附加以下可选字段：

```json
{
  "protocol": "hysteria",
  "version": 2,
  "server_port": 443,
  "port_hopping": {"start": 20000, "end": 21000}
}
```

`port_hopping` 只表达节点主机上要管理的 UDP 端口转发范围，不是 TLS/QUIC 或客户端配置。Node 应把该范围转发至同一配置的 `server_port`。客户端订阅仍从连接端口生成范围和可用的跳跃间隔；部分订阅格式只提供单端口，因此不能据此认定所有客户端均会跳跃。

自动 NAT 与 INPUT 均需要节点主机允许相关特权操作。标准 v9 安装器显式启用后，仅为实际 UDP 监听口维护 iptables-nft / legacy 的 IPv4、IPv6 INPUT，启动、配置变化和每 30 秒核对自身规则；本地关闭优先，自定义无启用环境变量时默认关闭。额外原生 nftables INPUT / firewalld 需人工处理，云安全组和 Docker 端口发布另行配置。重载后恢复存在窗口，面板保存成功不等于远端已允许 UDP；不修改提供商持久文件、默认策略或保存全规则。

## 更新和兼容行为

建议先备份并更新后端，再逐台更新 Node。无需数据库迁移、卸载插件或重建 NodeEndpoint CA。新版 Node 启动时会拉取已有合法范围；若旧配置使用不支持的格式，应在后台修正后保存。后续实际范围变更会发送到节点，未改动字段的重复保存不作为强制同步方式。

连接端口改成单端口后，GET 和 WebSocket 配置中均不再包含 `port_hopping`，新版 Node 据此撤销该节点所管理的转发。只修改 Hysteria2 连接端口也会在数据库提交后推送配置；回滚事务不会推送。轮询接口的 ETag 包含该字段，范围变更不会继续返回旧配置的 304。

既存数据库中的畸形范围、列表或不合法监听端口不会被猜测或纠正为 Root 规则；后端直接省略 `port_hopping`。这些旧记录的其他既有配置仍按原逻辑读取，订阅可能仍无效，应在后台改为合法格式并重新保存。协议版本不是 2 时同样不会生成此字段。

## 本地验证

`tests/Hysteria2/port_hopping.php` 使用内存 SQLite 和真实 Laravel 请求准备、校验、保存控制器、GET 配置控制器及 afterCommit observer，仅记录 Redis 推送内容，不访问生产服务：

```bash
php tests/Hysteria2/port_hopping.php
```

若借用另一份已安装依赖，可设置 `XBOARD_TEST_VENDOR=/path/to/vendor/autoload.php`。测试覆盖有效范围、输入拒绝、旧零值兼容、旧畸形值安全省略、GET/WS 一致、ETag 更新、撤销范围、事务回滚及其他协议兼容。节点实际 UDP 转发和连续 QUIC 传输需要独立运行测试，不能用本节的配置测试替代。
