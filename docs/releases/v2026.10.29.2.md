## 新装与旧站升级

原生 PHP-FPM 新站以 Root 执行一次发行包的 `init.sh` 流程：先降权安装锁定依赖、初始化数据库、安装并启用五插件，随后完成独立 HTTPS 入口、公共 CA 与助手初始化。已有有效入口仍会安装助手，保留原 CA 和入口配置。显式 `--skip-endpoint` 会将入口、公共 CA 和助手一起延期，五插件仍正常安装启用。

已有站点使用[本版归档升级说明](../installation/upgrade-2026.10.29.2.zh-CN.md)，保留原数据库、`.env` / APP_KEY、机器身份、CA、插件设置和管理员禁用选择。缺少的默认插件按原生同步规则安装启用，只有显式 `--enable-all` 会改变已有禁用选择。来源锁覆盖的官方旧版可接管升级，未知修改拒绝覆盖，较新版本不降级。

以 Root 执行本版归档升级、且不加 `--skip-endpoint` 时，`deploy-release.py` 调用原生升级协调器，为已有有效原生 HTTPS 入口安装或更新受限助手，授权范围与新初始化相同。网页请求不会自行创建 Root 服务。仅插件上传、手动源码升级，或显式跳过本次入口处理而尚未安装助手时，才需通过 Root SSH 单独执行 `--enable-web-manager`；已有入口和 CA 保留。助手缺失不阻止插件安装和启用，手动公共 CA / 状态导入继续可用。已有站点不重新执行应用全新安装或生成 APP_KEY。

## 登录、预览与任务恢复

独立页面从同源后台会话读取已有管理员凭据，仅在页面内存使用；服务端继续核验管理员身份。后台退出、切换账号、共享登录过期或接口返回 401/403 时，本页清理会话和敏感显示。“退出本页会话”保留主后台凭据，并暂停该标签页自动重登；点击“使用当前后台登录”可恢复。账号密码与手动 Bearer Token 验证保留作为回退。

网页固定任务包括入口配置、配置与状态刷新、服务器证书续签和入口防火墙。每次执行前都要生成有期限的预览，核对实际目标并输入完整确认文字。更改设置、计划过期或 Root 状态变化会拒绝旧计划。入口端口受 Root 策略限制，不能由网页开放任意端口。

同一计划使用持久任务身份，重复提交不会重新执行；响应不确定时保留原计划供同一请求重试。管理员与任务的关联写入数据库，应用缓存清空后仍可查询保留的本人任务。助手重启将未完成任务标记为中断，不自动重放；任务记录被清理时页面提示重新预览，助手可继续使用。阶段失败会保留已完成结果及安全错误说明，不把跨阶段操作宣称为整体原子回滚。

CA 与状态同步验证 Root 公共证书及指纹，不经 socket 返回根私钥或 CA 口令。证书区已有的管理员口令显式查看仍保留 60 秒自动隐藏、离页和退出清理。根 CA 轮换与私钥导出继续使用 SSH。

## 本机信任边界

助手只监听本机 Unix socket，按内核提供的进程 UID 授权。Root 私有策略固定应用、非 Root 网站身份、工具摘要及允许端口；网站输入不能选择任意 Root 命令或文件路径，应用 PHP 始终以网站用户执行。固定工具包保持原字节，助手对应用输出使用有界捕获，拒绝超限内容并终止对应进程组；公开错误不带应用日志、私钥或口令。

每站应使用与实际 PHP-FPM 进程一致的专用系统 UID。多个站点共用 `www` 时共享授权边界，不能将该助手视为站间隔离；仅修改 CLI 的 `--app-user` 不会改变 FPM 身份。
