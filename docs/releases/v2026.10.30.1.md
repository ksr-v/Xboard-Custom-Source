# v2026.10.30.1：Hysteria2 UDP 监听口自动放行

本版将 NodeEndpoint 更新至 `1.1.1`，新机器安装命令固定使用独立 Node `v1.13-orphan.8`。Node 在标准安装启用后管理本实例实际 Hysteria2 UDP 监听口的 INPUT 放行，并在启动、配置变化和每 `30` 秒检查中恢复自己的规则。单端口 Hysteria2 同样适用；端口跳跃 NAT 正确而 INPUT 仍阻断的节点无需再手工插入临时监听口规则。

## 自动放行边界

支持 Linux 主机 iptables-nft / iptables-legacy 的 IPv4 和 IPv6。INPUT 只开放实际 UDP 监听口，按监听地址与协议族限定，不将整个广告范围或 TCP 一并放行。每个网络命名空间只启用一个受管 Node 进程，同进程可含多个节点。Node 维护带实例所有权标记的运行时规则；停止、撤销和卸载只清理自己的规则。SIGKILL / 断电遗留规则在后续启用管理时严格核对归属再回收，正常停止清理与异常恢复分别处理。

标准 Node 安装器通过 `XBOARD_NODE_MANAGED_INPUT=1` 明确启用；`--skip-firewall` 设置为 `0`，升级保留已有关闭选择。本地 `firewall.managed_input: false` 优先；自定义服务没有启用环境变量时默认关闭，不能由网页或远端节点配置自行授予这项权限。

UFW 的兼容 iptables 布局和 iptables-persistent / netfilter-persistent 重载后的运行时规则可在后续周期恢复，等待30秒检查之外还包括串行命令耗时，存在阻断窗口。Node 不修改全局持久规则文件、不保存整个 ruleset、不改变默认策略。额外原生 nftables/firewalld INPUT base chain 本次需人工处理，按规则布局检测，不按 firewalld 进程状态判断；云安全组与上游 UDP 放行仍由管理员配置。详见[Hysteria2 操作说明](../operations/node-management-hy2.zh-CN.md)。

## 安装、升级与验证

新站使用[本版安装教程](../installation/install-2026.10.30.1.zh-CN.md)，已有面板使用[保留数据升级教程](../installation/upgrade-2026.10.30.1.zh-CN.md)，再逐台更新 Node。五插件在全新安装时自动安装启用；默认 Root 归档升级仍为已有有效原生 HTTPS 入口安装或更新受限助手，`--skip-endpoint` 将本次入口和助手处理延期。根 CA 轮换、私钥导出仍使用 SSH。

保留上一版同源管理员登录复用、Root 预览和完整文字确认、任务恢复及公共 CA 同步能力。助手按实际网站系统 UID 授权，多站需独立 UID；同一 UID 下的站点共享信任边界。

独立 Node v8 正式六项公开资产已完成大小、SHA-256 和 GitHub API digest 核验。本轮 Node 检查为 Go599项/15包、race129项/2包、真实 netns9项、Python94通过/1可选跳过；AMD64在 Windows/Linux 逐字重现，ARM64仅交叉构建。面板正式归档摘要、来源、逐成员、组件和隔离验收结果记录于随发行 JSON。Root 工具和助手保持不变，本轮未重跑助手 RPC、网页 UI 或助手参与的完整安装升级。历史 v2026.10.29.2 / Node v7 结果单列，实际来源和附件见[验证记录](../installation/release-2026.10.30.1-validation.zh-CN.md)。
