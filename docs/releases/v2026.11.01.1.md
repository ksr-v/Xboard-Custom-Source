# 2026.11.01.1：固定流量队列与 OPcache 部署说明

生产环境 `data-pipeline` 从每秒自动扩缩容改为 `simple` 固定分配。原生默认由 `traffic_fetch`、`stat`、`user_alive_sync` 三个队列各使用一个 worker，减少短周期上报时进程反复创建与回收。保留 `HORIZON_DATA_PIPELINE_MAX` 显式覆盖；值为 `6` 时各两个 worker。Docker 入口继续按资源导出进程预算，不统一改为三个。

aaPanel / PHP 8.3 FPM 教程补充 OPcache：实际安装并加载扩展，再核对 `128 MB / 16 MB / 20000`、`validate_timestamps=1` 和 `revalidate_freq=2`。仅写 ini 或查看 CLI 的缓存结果不能证明线上 FPM 已启用，详见[安装与 FPM 验证](../installation/aapanel.zh-CN.md#php83-opcache)。

本发行提供完整原生 `xboard.tar.gz`、`SHA256SUMS` 和来源、验证元数据。已有站点使用[本版升级步骤](../installation/upgrade-2026.11.01.1.zh-CN.md)，保留数据库、原 `.env` / APP_KEY、插件配置、机器身份与 CA，并按既有备份和维护流程部署。本版未另发固定 SSH 批量升级器；旧发行的固定升级器仍只对应其原归档。已有机器若仅应用这两项 Horizon 配置变化，参照[配置缓存与优雅切换边界](../installation/aapanel.zh-CN.md#horizon-fixed-workers)。OPcache 扩展需在 aaPanel 另行安装，源码升级不会替代该步骤。

本轮验证包括相关配置、语法及兼容检查，具体结果见[本轮验证记录](../installation/release-2026.11.01.1-validation.zh-CN.md)及发行附件。现场已验证队列配置的优雅切换与单次正常订阅；没有执行此版本完整归档的生产升级或吞吐测试。旧固定 tag、插件来源锁和既有发行验收记录保持各自归属。
