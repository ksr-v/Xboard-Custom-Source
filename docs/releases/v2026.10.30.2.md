# v2026.10.30.2：Node v9 兼容修复

本版将 NodeEndpoint 更新至 `1.1.2`，新机器安装命令固定独立 Node `v1.13-orphan.9`，独立 Node tools 为 `1.0.11`。已发布 Node v8、插件 1.1.1 和面板 30.1 保留原字节及验证记录。

## 修复范围

已确认混合大小写 ACME DNS 域名可能使 Order 与 CSR 的 literal 标识不一致。v9 在 ACME 入口和配置指纹统一名称处理，不降低 TLS 验证、不删除已保存证书，不改变 self / file / content 模式。该修复不代表任意域名、通配符、尾点或 IP 均能通过真实 CA 的签发策略。

现场已确认 nftables `0.9.0`、内核 `4.19.0-21`：JSON 查询退出码为 0、返回 `nftables: null`，独立纯文本 `list tables` 也成功且为空。v9 只在该独立空表检查成立时兼容 null，其他异常、未知结构和非空结果仍拒绝。转发计划改用 `ip` / `ip6` 家族 NAT、数值优先级与未挂钩的完整所有权标记规则，避免依赖旧环境不支持的 inet NAT / table comment；仅对校验通过的旧 v8 inet 资源作受控迁移，不清空外部规则。

保留 v8 的 owned UDP INPUT、单监听口范围、关闭选择、恢复窗口及防火墙兼容边界，详见[节点操作说明](../operations/node-management-hy2.zh-CN.md)。只更新面板或插件不能更新远端 Node。已有节点使用保留身份、Token、CA 与配置的 `upgrade`，不执行新装 `REPLACE`，不清空证书缓存。

五插件新装自动安装启用，升级保留禁用选择。默认 Root 归档升级仍处理已有有效原生入口的助手，`--skip-endpoint` 保留延期语义；仅插件上传或手动源码升级不会自行创建 Root 服务。根 CA 轮换、私钥导出和本机 UID 授权边界保持原样。
